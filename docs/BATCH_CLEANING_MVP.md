# 整文件校对 MVP 任务卡

## 一句话目标

为已经拥有结构化转写结果的用户提供独立入口：一次把单个文件的完整转录交给远程模型找错，本地只应用安全修改，原稿始终保留。

## 必须完成

1. 在“可信数据”中选择目录并递归扫描原始转写 JSON。
2. 只接受包含 `source` 和有效 `segments` 的结构化转写，排除已有派生结果和普通配置 JSON。
3. 使用设置中已经真实测试通过的 OpenAI Chat Completions 兼容接口，不限定模型厂商或中转站。
4. 每个文件正常情况下只发起一次整文件请求；模型只返回错误清单，不重写、不润色、不总结全文。
5. 调用前估算 Token。超出用户填写的模型上下文窗口时明确停止，不静默回退为小块校对。
6. 本地核对片段编号、原文位置和置信度，拦截数字、否定词和大幅改写等高风险建议。
7. 每个原始 JSON 写出 `.verified.json` 与 `.corrections.json`，不修改、不移动、不删除原稿和视频。
8. 一个文件失败时记录错误并继续后续文件；已有两种完整结果时自动跳过。
9. 支持暂停、继续和取消。暂停在当前整文件请求结束后生效，已完成结果保留。
10. 页面显示文件数量、待处理、已完成、已应用修改、待复核和每个文件的预计 Token。

## 明确不做

1. 不自动建设完整知识库。
2. 不在校对完成后自动导入索引。
3. 不覆盖原始转录，也不让程序猜测多个派生版本中该用哪一份。
4. 不把单个文件自动拆成小块来绕过上下文上限。
5. 不恢复旧的模型 A / 模型 B 逐条交叉验证页面。

## 文件边界

```text
原始目录（只读）
  001.json
  002.json

可信结果目录（后续唯一入口）
  <source-hash>-001.verified.json
  <source-hash>-001.corrections.json
  <source-hash>-002.verified.json
  <source-hash>-002.corrections.json
```

`.verified.json` 保存最终文本、可信状态、源视频路径与起止秒数；`.corrections.json` 保存原文、模型建议、本地应用决定和原因。

## 完成标准

1. 一个含多个片段的文件只调用模型一次，且请求包含全部片段。
2. 数字、否定词、低置信度和原文不匹配的修改不会自动应用。
3. 原始文件内容和修改时间不因可信处理而变化。
4. 可信关键词检索只返回 `knowledge_ready=true` 的片段，并能打开原视频定位到开始时间。
5. 热词生成结果可留存、重命名、删除并在后续转录任务中直接复用。
6. 历史记录可删除，但删除只作用于历史索引，不删除媒体、转录结果或热词集。
7. 全部自动测试、Python 编译、前端语法检查和 GUI smoke test 通过。
